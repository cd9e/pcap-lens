# 安全检查与修复记录

检查日期：2026-09-09。修复版本：0.1.1。

## 检查范围

本次检查覆盖本地抓包读取、pcap/pcapng 容器和网络协议解析、TCP/HTTP/DNS 分析、过滤表达式、Worker 生命周期、Webview 展示与消息处理、正文导出、Wireshark 启动及 npm 依赖。代码审查结合了恶意输入回归和真实浏览器/扩展宿主验证。

## 发现并修复的问题

| 问题                                 | 原因与影响                                                                                                          | 修复                                                                                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 捕获内容导致资源放大                 | 原先 gzip 只限制单条解压结果，多条压缩响应可累计占用大量内存；跨包 HTTP 字段重复携带长字符串，消息/包数量也缺少预算 | 增加文件、包、消息、头部和累计正文预算；限制重复字段预览；超过 gzip 预算时保留压缩字节并标记失败，累计保留预算耗尽则终止分析             |
| 深层过滤表达式耗尽调用栈             | 5000 层括号可复现 `RangeError: Maximum call stack size exceeded`                                                    | 在编译前限制字符/token 数，在递归过程中限制深度，使用可定位的 FilterError，保留旧过滤结果                                                |
| 重复初始化与后台任务失控             | `ready` 在异步读取结束前可多次进入，启动多个 Worker；Worker 缺少超时和无结果退出处理                                | 缓存进行中的 Promise；增加初始化锁、取消信号、15 秒超时和退出处理；编辑器关闭时取消任务                                                  |
| 文件读取边界不足                     | 路径 stat 与 readFile 分离，没有检查普通文件类型；路径替换、增长文件或设备文件可能绕过预期读取边界                  | 对同一个文件描述符检查并有界读取，非阻塞打开后拒绝设备/FIFO/目录，限制字节数，检测读取期间文件增长，确保关闭句柄                         |
| 界面可被大数据拖慢                   | 数据包/流/统计列表和正文预览一次性渲染大量内容                                                                      | 首批 200 条、手动扩展；正文文本/JSON 预览限制到 256 KB；完整保留正文仍可导出                                                             |
| 可执行文件查找与重复导出缺少明确约束 | 裸 `wireshark` 依赖平台 PATH/CWD 查找；重复消息可能创建多个保存对话框                                               | Wireshark 使用经过检查的绝对路径，忽略工作区的可执行路径设置，Linux PATH 排除相对/空目录，关闭 shell，固定启动 cwd；导出参数检查及并发锁 |

最后一项属于防御性加固；本次未复现通过抓包内容执行任意代码。原有 React 文本转义和 Webview CSP 已保留，新增测试确认 `<img>` 和 `<script>` 流量内容不会变成可执行 DOM。正文导出的目标仍由用户在保存对话框选择，抓包内容不能指定路径。

## 当前资源上限

- 文件：8 MiB；20,000 个数据包；每 section 1,024 个接口。
- HTTP：整份抓包最多 2,000 条消息；每条头部 64 KiB / 128 个字段；首行识别窗口 8 KiB。
- 正文：每条最多保留 4 MiB；整份抓包累计最多保留 8 MiB。gzip 的最大解压输出同时受单条及剩余累计预算约束。
- 跨包 HTTP 字段预览：名称最多 128 个字符，值最多 256 个字符；完整头部可在 HTTP 详情和原始字节查看。
- DNS：最多尝试解析 2,000 条消息；每条 question + answer 总数不超过 256，展开名称不超过 255 字节。
- VLAN：最多 16 层；IPv6 扩展头保留原有的 16 层限制。
- 过滤器：4,096 个字符、512 个 token、32 层递归。
- Worker：256 MiB V8 old-generation 限制，15 秒超时。此堆限制并非整个 VS Code 进程的总内存上限。
- 界面：表格/流分批展示，文本预览 256 KiB，诊断区域首批最多展示 200 项。

这些边界适用于当前约 10–2000 KB 的日常抓包场景。此前文档中的 64 MB 文件和 16 MB 正文上限已收紧。超出分析预算会明确报告错误，不将不完整分析结果伪装成正常结果。
